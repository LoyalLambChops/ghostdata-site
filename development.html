October 30, 2026BUILD NOTE / 006

Small counters. Useful information.

A separate local-player effect panel joins the rails in build 1.3.9.

Aessina shows friendly minion deaths out of 20, how many remain, and when the threshold is ready. Starsurge shows the friendly death count, and Herald uses the actual amount recorded by the game. The frames sit below your rail within the existing safe area, preserving space for your hand.

Unknown totals stay unknown when game evidence is incomplete. These are the first supported effect counters, not a promise of every mechanic. Your match data and definitions remain local.

The Update result now names the installed version when nothing needs replacing. Current manuals were refreshed, and release checks catch stale guide versions. Older development notes remain dated history.

Read the release notes and download 1.3.9.

October 29, 2026BUILD NOTE / 005

Observation first. A tighter beta.

Beta testing found four bugs worth fixing now.

Build 1.3.8 prevents discarded private Assemble choices from appearing on the opponent rail before gameplay reveals the actual card. GhostData should track what you can observe, and this patch tightens that boundary.

Godfrey's recoverable-overdraw list now follows the real cards instead of including extra history-display copies. Names and discounted costs stay in their own rail section, in capture order, and entries leave the list when they return to hand. Grueling Trial's rail hover resolves its own effect text from the installed game's definitions and observed components.

Deck identity is now saved during each active game. A missed sensor read at the end should no longer permanently lose the deck name. Recovery uses evidence tied to that specific game, never whichever deck you select later. Older records without that evidence stay unidentified rather than being guessed.

The fixes were checked with synthetic regressions and local reconstruction of the reported games. This remains an unsigned beta with bounded mechanic coverage; it is not a claim that every card has been field-tested. Your history stays local.

Download the 1.3.8 Windows installer, or use GhostData's Update button. Release notes and checksums.

— LoyalLambChops

October 27, 2026BUILD NOTE / 004

Phantom · Beta 1 is ready to try.

One installer. Local tracking. Your games, your data.

Download GhostData 1.3.7 for Windows and run the installer. Python and .NET are included, with Start Menu and optional Desktop shortcuts. The clean-machine installation test and a Standard match were completed on the prior candidate; the latest build corrects hand-hover behavior and passes 261 Python regressions and 67 UI/lifecycle checks.

GhostData configures Power.log logging and imports card definitions from the installed game automatically. If logging is enabled while Hearthstone is already open, the game may need one restart. No manual card-file download or developer tools are needed.

Hand hover now shows only supported summon, replay and stored-card results, such as Ectoplasm’s own stored minions. Ordinary hand cards do not open a duplicate description. Rail hover keeps full descriptions and broader tracked draw/Discover context. Unknown positions stay unknown, and possible random results are never labeled as guaranteed.

This is a beta: some specialized mechanic previews remain incomplete, and turn timers and additional counters come later. I’m choosing useful features that fit GhostData, with your match history and analytics staying on your machine.

The first beta is unsigned, so Windows may show a warning or block it under its security policy. The installer is all most players need; the portable ZIP is an alternative. Read the release notes and download checksums, or browse the MIT-licensed source.

Found a bug? Tell me what happened in Discord or by email. Review logs and screenshots for personal information before sharing them.

— LoyalLambChops

October 22, 2026BUILD NOTE / 002

Getting GhostData ready for a simple install.

Players should be able to download an app, install it, and start using it. They shouldn’t need to build it first.

The 1.3.0 packaging candidate is a step toward that. It includes a Windows installer, a branded Start Menu shortcut, an optional Desktop shortcut, and Python and .NET 10 bundled with the application. A portable ZIP remains an alternative.

Keeping updates out of your history

Program files and match data live in separate locations. Updates replace the application payload while keeping uninstall support intact. Uninstalling removes the program and shortcuts while preserving the external history folder. Launching the app twice now brings the existing dashboard forward.

What has been checked

The candidate passed 184 Python regression tests and 40 UI and instance-lifecycle checks. An isolated installation test checked shortcuts, UI rendering, reinstall behavior, successful updates, rollback after a deliberately failed startup, and uninstall while preserving test data. These checks ran on the development machine, not a clean Windows VM.

What comes before a public download

  • License and signing decision: resolved October 25—MIT, with an unsigned initial beta. See the Phantom update.
  • Test the installer on a clean supported Windows system.
  • Complete remaining live-game, reconnect and display-scaling acceptance.
  • Validate the actual public download and update path.

This is a packaging candidate, not a public release. The download will be linked on the main page when it’s ready.

October 22, 2026DEV DIARY / 001

Why I’m building a local tracker.

I wanted to test decks, keep a full record of my games, and understand the results without sending that history somewhere else.

That’s why I created GhostData. A tracker should help during the game, and a dashboard should make it easy to look back afterward. Your match history should stay your match history, saved on your own machine.

Function before beauty

The rails focus on readable text and observed card states. Quests, Secret possibilities, and recoverable overdraw have their own treatment. The dashboard brings together deck versions, match history, class matchups, and charts. Screenshots on this site use synthetic sample data so nobody’s personal history has to be published.

A small stack with a specific job

Avalonia handles the desktop interface. The open-source UnitySpy sensor reads local client state. GhostData’s own Python engine combines that with game logs to track observed events and build local statistics. Unknown information stays unresolved; the app is not a tactical adviser or an automated player.

Where this is going

The goal is a free, open-source application built around local data and useful analysis. Standard is the focus. More live validation and release work remain, and full-card artwork is not a shipped feature; the current hover display is text-only.

If you have ideas, questions, or something you’d like to see tested, send me a note. I’m building this because I want to use it too.

— LoyalLambChops
